About libsec

A focused feed of vulnerabilities that matter to people running web servers and web applications.

How it works

  1. Collect. One collector per source, each on its own schedule, with conditional requests and deltas (no full re-downloads).
  2. Normalize & deduplicate. CVE, GHSA, PYSEC, GO and vendor IDs are merged into one record with aliases. Later facts (new CVSS, KEV listing, fixed versions) become events on the same record instead of duplicate posts.
  3. Filter. Only records that match the product catalog go further. The Linux kernel is included only for exploited or high-severity issues.
  4. Prioritize. A transparent rule combines vendor/CNA CVSS, CISA KEV and EPSS. CVSS is never invented: it is shown with its source.
  5. Analyze (AI). A model writes a short summary, preconditions, action and an urgency score for a typical web server, using only the collected facts and a strict JSON schema. Fixed versions it mentions are checked against source data in code. AI text is always labelled.
  6. Publish. This site, RSS, JSON API and Telegram (urgent items instantly, the rest as a daily digest).

API

  • GET /api/v1/vulns?product=nginx&priority=CRITICAL,HIGH&kev=1&since=2026-11-01&limit=50 — feed (add all=1 for history beyond 45 days)
  • GET /api/v1/vulns/CVE-2024-4577 — one record with affected versions, references and timeline (any alias works)
  • GET /api/v1/products — catalog
  • GET /feed.xml?product=php&prio=CRITICAL,HIGH — RSS
  • OpenAPI docs

Caveats

This is an MVP. Matching by product names is heuristic and can miss or over-include items; AI summaries can be wrong — the sources and the version table are authoritative. No exploit code is published here.
