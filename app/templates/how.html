{{ _('How {b} works', b=BRAND) }}

{{ _('{b} watches vulnerabilities in popular server and website software, keeps only what matters and tells you in plain words what to update.', b=BRAND) }}

{{ _('How the database is built') }}

  1. {{ _('Every 10–60 minutes the service checks the main open sources: the global CVE registry, the GitHub and OSV vulnerability databases for libraries, the CISA list of vulnerabilities that are already being exploited, the EPSS exploitation forecast and the vendors’ own security pages (for example, nginx).') }}
  2. {{ _('It keeps only what concerns 50 popular products for websites and servers: PHP, Python, MySQL, PostgreSQL, nginx, Apache, Tomcat, OpenSSL, Docker, WordPress, Laravel, Django and others.') }}
  3. {{ _('One vulnerability is often described by several sources under different IDs. The service merges them into one record, so there are no duplicates.') }}
  4. {{ _('Each record gets an urgency level: critical, high, medium or low. The rule is open: it uses the vendor’s score, whether the vulnerability is already being exploited, and how likely an attack is.') }}
  5. {{ _('If the situation changes, for example attackers start exploiting the vulnerability, the record moves back to the top of the feed.') }}

{{ _('What the AI does') }}

  1. {{ _('Every 10 minutes the AI takes the fresh records.') }}
  2. {{ _('It rewrites the technical text in plain words: what is broken, who is affected, with which settings it is dangerous, and what to do.') }}
  3. {{ _('It gives its own estimate of how dangerous this is for a typical server, and explains why.') }}
  4. {{ _('It names the versions with the fix. The program checks every version against the sources, so a version made up by the AI does not get through.') }}
  5. {{ _('It translates the summary into 7 languages.') }}
  6. {{ _('AI text is always labelled, and links to the original sources are always next to it.') }}

{{ _('Where to get it') }}

  • {{ _('The feed on this site: the last 45 days, filters by product and urgency, search.') }}
  • {{ _('Telegram: urgent items right away, the rest as a daily digest.') }}
  • {{ _('RSS, also for a single product or urgency level.') }}
  • {{ _('A JSON API for automation: a script or an AI agent can check your servers and update them on its own. Examples are below.') }}

{{ _('Why it is useful') }}

  • {{ _('Everything in one place. No need to follow a dozen sites and mailing lists.') }}
  • {{ _('Only your stack. No thousands of vulnerabilities in software you do not use.') }}
  • {{ _('Clear priorities. Urgency follows an open rule, and what is already being exploited is highlighted.') }}
  • {{ _('Clear actions. Each record says which version to update to and with which settings the vulnerability is dangerous.') }}
  • {{ _('Fast. New records appear 10–60 minutes after publication.') }}
  • {{ _('No guesswork. Facts come only from official sources, danger scores are never invented, version numbers are checked.') }}
  • {{ _('For people and machines. The site in 8 languages, Telegram, RSS and a JSON API.') }}
  • {{ _('Free and open. No sign-up, the source code is on GitHub.') }}
