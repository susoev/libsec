# libsec — исходное ТЗ владельца (2026-11-20)

Сервис-трекер уязвимостей базового веб-стека: проверяет уязвимости из разных источников и выводит их на сайте лентой постов.

Архитектура:
- у каждого источника свой скрипт и свой интервал;
- скрипты загружают данные из источников;
- свежий контент (если он есть) анализирует ИИ и выставляет оценку;
- сервис публичный, посты репостятся в TG;
- сайт мультиязычный.

Стек для отслеживания: php / python / mysql / nginx / apache и другие самые популярные продукты для веб-серверов и веб-приложений.

Боевой домен в планах — basesecurity.com с языками. MVP — https://libsec.alid.in.
Задача владельца: собрать готовый MVP как можно быстрее; неясное решать самому, владелец потом поправит.

## Проектная записка (обсуждена с владельцем, база для MVP)

### Схема
Сбор (collectors) → raw_items (сырые данные + хэш) → нормализация и дедупликация (CVE/GHSA/DSA/USN → одна сущность, привязка к каталогу продуктов) → фильтр релевантности (только продукты из каталога) → ИИ-анализ (резюме, кого касается, что делать, оценка; строго по собранным данным, JSON-схема) → пост (канонический EN) → перевод (fr/de/es/hi/ru…) → сайт, TG-каналы, RSS/JSON API.

### Компоненты
1. **Коллекторы.** У каждого источника свой скрипт и интервал. `fetch()` возвращает `{source, external_id, url, payload, fetched_at}`. Используются ETag/If-Modified-Since и дельты: lastModStartDate у NVD, modified_id.csv у OSV, дельты cvelistV5. Для каждого источника хранится состояние: последний запуск, курсор, число новых записей, ошибки. Отдельный алерт на «молчащий» источник.
2. **Нормализация и дедупликация.**
   - `vulnerability`: канонический ID (обычно CVE) и `aliases[]`.
   - `event`: опубликована / появился CVSS / добавлена в KEV / вышел фикс в Debian / появился публичный эксплойт.
   - `post`: один пост на уязвимость, со временем дополняется событиями.
3. **Каталог продуктов.** У каждого продукта набор сопоставлений: CPE vendor/product, purl/экосистема OSV, имена пакетов в дистрибутивах, GitHub-репозиторий, ключевые слова.
4. **ИИ-анализ.**
   - Только для записей, прошедших фильтр.
   - Дешёвая модель классифицирует, сильная пишет пост.
   - Вход — только собранные факты. Выход — строгая JSON-схема: summary, affected_versions, fixed_versions, attack_vector, preconditions, action, our_score, score_reasoning.
   - CVSS, EPSS и KEV показываются отдельно от своей оценки. ИИ не придумывает CVSS.
   - У каждого факта есть ссылка на источник.
5. **Публикация.**
   - Сайт с серверным рендерингом.
   - TG: High/Critical и KEV сразу, остальное дайджестом раз в день.
   - RSS и JSON API.

### Источники
| Источник | Что даёт | Как забирать | Интервал |
|---|---|---|---|
| CVE List (cvelistV5) | все CVE | дельты | 5–10 мин |
| OSV.dev | пакеты PHP/Python/npm, точные версии | modified_id.csv | 15 мин |
| GitHub Advisory DB | GHSA | API | 15 мин |
| CISA KEV | эксплуатируется в атаках | JSON | 1 ч |
| EPSS | вероятность эксплуатации | CSV | 24 ч |
| NVD API 2.0 | CPE, обогащение | lastMod | 1–2 ч |
| Debian / Ubuntu / RHEL | статус фикса | JSON / OSV / OVAL | 30–60 мин |
| вендоры: nginx, php.net, Apache, Oracle CPU, MariaDB, PostgreSQL, Redis, OpenSSL… | первоисточник | RSS / HTML | 30–60 мин |
| oss-security | ранние раскрытия | почта | по событию |

NVD больше не основной источник: с 15.04.2026 NIST подробно анализирует только приоритетные CVE.

### Стартовый каталог (~40 позиций)
- **Языки и рантаймы:** PHP, Python, Node.js, Ruby, OpenJDK, Go.
- **Веб-серверы и прокси:** nginx, Apache httpd, HAProxy, Caddy, Varnish, Traefik, Tomcat.
- **БД и кэши:** MySQL, MariaDB, PostgreSQL, Redis/Valkey, MongoDB, Memcached, Elasticsearch/OpenSearch.
- **Системное:** OpenSSL, OpenSSH, glibc, curl, sudo, systemd, ядро Linux (только высокий приоритет).
- **Контейнеры:** Docker, containerd, runc, Kubernetes, ingress-nginx.
- **Фреймворки и CMS:** Laravel, Symfony, Django, Flask, Express, Next.js, WordPress core, Drupal, Joomla.
- **Обвязка:** phpMyAdmin, Composer, pip, ImageMagick, Exim, Postfix, Grafana, Jenkins, GitLab.

Плагины WordPress не берём: они утопят ленту.

### Мультиязычность
- Языки по ISO 639-1 (hi, а не in).
- Пути `/fr/` проще поддоменов. Нужны hreflang и canonical.
- Канонический текст на EN, переводы делаются из него. CVE ID, версии, команды и имена пакетов не переводятся.
- Переводы кэшируются. Начинаем с 3–4 языков.
- TG-канал на каждый язык.

### Риски
- Ошибки ИИ: помогают структурированный вывод, сверка версий кодом, пометка AI-generated и журнал правок.
- Шум: нужен жёсткий фильтр по каталогу.
- Эскалации (появился CVSS, добавлена в KEV): нужны правила, когда это новый пост в TG, а когда тихое обновление страницы.
- Лицензии: OSV и GHSA — CC-BY 4.0 с атрибуцией, NVD и CISA — общественное достояние. Тексты пересказываем.
- PoC-код не публикуем.
- HTML-парсеры хрупкие: нужны тесты на снимках.
- Лимиты TG: около 20 сообщений в минуту, 4096 символов — нужна очередь.

### Улучшения на потом
- Персональные подписки на свой стек.
- «Касается ли меня» по версии.
- Статус фикса по дистрибутивам.
- Готовые команды обновления и mitigation.
- Недельный дайджест.
- Платный API и вебхуки.

### Порядок запуска
1. Каталог ~20 продуктов; источники cvelistV5 + OSV + KEV + EPSS; дедупликация; сайт EN без ИИ (шаблонные посты).
2. ИИ-резюме и оценка, TG-канал EN, RSS.
3. Трекеры дистрибутивов и вендоров, события эскалации.
4. Языки (ru, es, fr, de, hi), персональные подписки.
