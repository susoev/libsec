# Решения по MVP (2026-11-20)

Принято без владельца; всё можно пересмотреть.

## Хранилище: SQLite (WAL), не PostgreSQL
- Один писатель (воркер) и читатели (сайт). Объём MVP — десятки МБ. SQLite в WAL-режиме справляется без отдельного сервера.
- PostgreSQL на сервере не установлен, а MySQL занят другими проектами.
- Схема переносится в Postgres почти один к одному (`app/libsec/db.py`), если понадобятся очередь с `SKIP LOCKED` или несколько воркеров.

## Стек
- Python 3.14 в venv `~/venvs/libsec`.
- Сайт: FastAPI + Jinja2 с серверным рендерингом, юнит `libsec`, uvicorn на 127.0.0.1:8795 за nginx.
- Воркер: один процесс `libsec-worker` со своим планировщиком. Интервал каждого источника хранится в таблице `sources.interval_sec` и меняется без деплоя. Отдельные systemd-таймеры не нужны: по ним сложнее вести состояние и алерты.

## Модель данных
- `raw_items` — сырые записи источников. Хранятся только совпавшие с каталогом или уже известные уязвимости.
- `facts` — нормализованные факты одного источника об уязвимости. Строка `vulns` каждый раз пересчитывается из всех фактов, поэтому результат детерминирован и не зависит от порядка прихода данных.
- Канонический ID — CVE. Если CVE нет, используется GHSA или OSV. Когда у GHSA появляется CVE, запись переименовывается и все связи переносятся.
- Если advisory упоминает два разных CVE, они остаются двумя уязвимостями: CVE друг в друга не сливаются.
- `events` — события: published, scored, kev, fix, epss_high. Публикация в TG срабатывает от событий, поэтому дублей постов нет.

## Источники (этап 1 + часть этапа 3)
- **CVE: cvelistV5 delta-релизы** — накопительный zip «изменения с полуночи UTC», выходит каждый час, проверяем раз в 10 минут; для прошлых дней — `end_of_day`. Без git clone, ~5–12 МБ в сутки. Бэкфилл — 30 дней.
- **OSV.** Бэкфилл — полная история пакетов каталога через `/v1/query`. Дельты — `modified_id.csv` с ETag. MAL-* (вредоносные пакеты) пропускаем. GitHub Advisory приходит отсюда (GHSA в OSV), отдельный коллектор GraphQL не нужен.
- **CISA KEV** — JSON с ETag.
- **EPSS** — API FIRST, только наши CVE, раз в сутки после выхода новой даты.
- **cveapi** — CVE-запись из CVE Services для уязвимостей, пришедших из OSV или KEV без записи cvelist: старые CVE из KEV и история пакетов.
- **nginx.org** — первый вендорский парсер: точные границы версий и оценка nginx.
- **NVD не используем:** с апреля 2026 он неполный, а CPE даёт и ADP CISA в самой CVE-записи.

## Каталог и шум
- 50 продуктов в `app/libsec/catalog.py`. Продукт распознаётся по vendor|product (регэкспы, сверены с реальными данными cvelist и KEV), CPE, packageName (дистрибутивы, Red Hat), координатам OSV и KEV vendorProject|product.
- **Ядро Linux** (`high_only`) — 500+ CVE в день без оценки. Берём только KEV, CVSS ≥ 9, сетевой вектор с CVSS ≥ 8 или EPSS ≥ 10%. Остальные CVE ядра даже не сохраняем.
- **Плагины WordPress не берём:** в каталоге только ядро WP (как в ТЗ).
- **Лента — окно 45 дней** по `feed_ts = max(published, kev_added)`, поэтому старая уязвимость, попавшая в KEV, поднимается наверх. На странице продукта — вся известная история.

## Оценки
- CVSS не придумываем. Порядок выбора: CNA 3.1 → CNA 3.0 → CNA 4.0 → CISA-ADP → GHSA (OSV). Источник оценки всегда показан. Для OSV оценка CVSS 3.x считается из вектора кодом.
- **Priority (правило, без ИИ):**
  - KEV → CRITICAL, а при CVSS Medium/Low → HIGH;
  - иначе — полоса CVSS;
  - EPSS ≥ 50% поднимает приоритет на одну ступень;
  - без оценки — UNRATED.
- **Своя оценка ИИ** (`our_score`, «насколько касается типичного веб-сервера») показывается отдельно и подписана как AI.

## ИИ
- Anthropic API, модель `claude-opus-5-5`, effort `medium`.
- Ответ — строгая JSON-схема (`output_config.format`), включены server-side fallbacks на случай отказа.
- Вход — только собранные факты. Исправленные версии из ответа сверяются кодом с источниками: неподтверждённые отбрасываются и помечаются. Ссылки — только из входных refs.
- Кэш по хэшу входных фактов: повторный вызов только при изменении данных.
- **Ключ:** `.secrets/ai.env` (`ANTHROPIC_API_KEY`). В хранилище он называется `CLAUDE_API_CA`, адрес внесён в `secrets.map.json`.
- **Пока ключа нет** — запасной путь через `claude -p` (подписка): только CRITICAL/HIGH/KEV за 7 дней, не больше 4 в час.
- Оценка стоимости через API: ~$0.03 на уязвимость, 10–20 новых в день → < $1 в день.

## Telegram
- Очередь `tg_queue` с лимитом 15 сообщений в минуту и обработкой 429.
- **Сразу постом:** новые CRITICAL/HIGH или KEV, «теперь эксплуатируется» (KEV) и повышение оценки до HIGH/CRITICAL.
- **Остальное** — дайджестом раз в сутки в 09:00 UTC.
- Срочный пост ждёт ИИ-резюме до 20 минут.
- События старше 36 часов — бэкфилл, в TG не уходят.
- Канал задаётся в `LIBSEC_TG_CHAT` юнита `libsec-worker`. Пока канала нет — тестовый режим: топик Sec, не больше 3 постов в сутки.

## Сайт
- Пока только EN, без языкового префикса.
- Для языков план — пути `/ru/`, `/es/`… (а не поддомены): общий авторитет домена, один сертификат, hreflang и canonical. Переводы — из канонического EN с глоссарием, с кэшем.
- `noindex` до выхода на боевой домен.
- RSS: `/feed.xml?product=&prio=&kev=`. API: `/api/v1/vulns`, `/api/v1/vulns/{id|alias}`, `/api/v1/products`, OpenAPI — `/api/docs`.
- `/status` — состояние коллекторов. Алерты в топик Sec: источник падает 3 раза подряд или cvelist молчит больше 6 часов.
